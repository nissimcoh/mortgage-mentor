# Final reliability review — October 18, 2026

## Changes after the UI/performance review

- `updateScenario` returns the canonical saved name and the exact `updated_at`
  generated by the database. The calculator updates its edit context after
  success, so subsequent saves use the new concurrency token and the banner
  and next save dialog show the current name. Ownership predicates, RLS and
  stale-write rejection remain in place; the client never generates a token.
- Market sources suppress repeated failures for 120 seconds per source and
  server worker. Concurrent reads still share one in-flight load. The next
  request at the retry boundary can recover; successful snapshots remain in
  Next's persistent cache and failures/fallbacks are never stored there. This
  is not a distributed outage circuit breaker across all Vercel instances.
- Supabase refresh cookies reach both the downstream request and the response
  returned to the browser. The installed SSR SDK's private/no-store headers
  are also preserved, including locale redirects. Server authorization still
  uses `getUser`; no authentication configuration was changed.
- The existing responsive layout, date formatting, comparison chart, session
  presentation, failure handling and unused asset cleanup changes are retained.

## Verification

- 743 offline tests pass; two explicit network diagnostics are skipped in the
  normal run. This adds ten regression cases to the prior 733-test suite.
- New tests cover two saves without remounting, exact fractional timestamp
  preservation, stale/missing/unauthenticated update outcomes, cold-source
  failure cooldown/retry/isolation/synchronous failure, and refresh cookies
  plus cache-prevention headers on localized requests and redirects.
- TypeScript, ESLint, production build and all 27 route smoke checks pass.
- Real authenticated browser: create a synthetic scenario, edit its amount and
  name twice consecutively without reloading, and reopen the original. Both
  updates persist and each subsequent dialog uses the latest saved name.
- Save as new creates a second synthetic scenario. Real saved comparison
  reconstructs both historical charts, displays the correct principals and
  allows selecting the final month without changing the static chart paths.
- Comparison was inspected visually at 320px and desktop widths. The admin
  page was checked read-only at 320px and 1440px; no document overflow.
- Hebrew and English missing routes return localized 404 pages at 320px and
  390px, with no document overflow.
- Both test-created scenarios were deleted through their own actions menus.
  The three pre-existing saved scenario IDs remain unchanged. No pre-existing
  scenario, user, or role was modified.

Browser screenshots and session-related diagnostic output stay in ignored
`output/playwright/`. Environment files remain ignored. No database move,
schema migration or authentication-setting change was performed.

## Deferred

- `getClaims()` is not substituted for the current server authorization flow
  in this change; that needs a separate signing-key and revocation-semantics
  review. Client `getSession()` remains presentation-only and may refresh an
  expiring session rather than always completing without a network request.
- PDF term/reset phrasing is a cosmetic follow-up.
- The unused admin-delete module is not registered in the current built
  Server Action manifest; no administration mutation UI was introduced.

The earlier calculation calibration and its documented fixed-cash payoff
rounding distinction remain in [CALCULATOR_REVIEW.md](CALCULATOR_REVIEW.md).
